# Kalamos ruled-writing workspace

This directory is the canonical source for the reusable ruled handwriting editor. The current Write,
Scribe, To-do and Books builds receive it through the sibling `features/writing/android` Gradle
library; no app copies or links to another app's source.

## Ownership

- TypeScript, CSS, tests and bundle configuration live here.
- `npm run build:android` generates `write-workspace.js` and `write-workspace.css` into
  `../android/src/main/assets/web/`.
- App overlays decide when and how to enter the workspace. Editing, tools, persistence protocol and
  native-ink handoff stay in this feature.
- The generated Android assets are build products. Do not edit them directly.

`openNotebook(id)` is the current Write document host. The workspace also retains
`openWorkspaceNotebook(id)` compatibility for a direct editor host, but the old Notes Planning UI
and its legacy renderer are not present in this repository.

Both host modes share native low-latency writing, Insert Space, Blank Lines/caret placement, erase,
selection/move/delete, magnified writing, undo/redo and optional handwriting recognition.

## Build and verify

```bash
npm ci
npm test
npm run typecheck
npm run build:android
```

Then build the affected app from the repository root. No sync or vendoring step exists.

Native ink and e-ink refresh behavior require the physical device. Browser tests validate routing,
layout, tools and persistence contracts only.

## Storage compatibility

The sidecar schema intentionally retains its existing `write2.sidecar` magic and compatible file
names. These are persisted-data identifiers, not a source or build dependency. Renaming them would
require an explicit document migration.


## Notebook page overview

The toolbar navigator reads `previous / overview + current/total / next` in compact and expanded
layouts. The overview supports multi-page selection, copying (including another notebook),
reordering/position moves, choosing a shelf cover and removal. The full-screen dialog uses readable action rows, numbered real-page previews with corner selection
boxes, a page slider and bottom-right grids for 4, 9 or 16 pages per view. It starts on the active
page's batch. Back/Escape returns to the same editor; hardware page keys navigate overview batches.
Native ink explicitly hands ownership to the dialog after checkpointing, so the dialog is visible
above the retained surface. Pending AI publication waits while a writing dialog is open. There is no Undo button in this manager. Page mutations preserve original
source/sidecar files and retain the preceding manifest in `planning.pages.previous.json`; previews
are generated from the saved vectors, not native screenshots. The ordinary fast page-turn and Zoom
handoff continue through the existing sheet controller.

Notes and Agent load the same opt-in writing presentation, `features/writing/workspace/src/kalamos/notes-writing-ui.css`, generated by `build:android`. Toolbar glyphs come from the neutral runtime `js/toolbar-icons.js`. Neither host maintains a writing UI copy; other writing hosts retain their existing presentation.


## Layout transaction verification

`penWorkspace.layoutTransactions.test.ts` exercises actual pointer gestures and checks both model
vectors and DOM preview transforms. It covers repeated/cancelled moves, mixed groups near other
words, page-boundary clamping, signed spacing, all 24 orderings of horizontal/vertical +/- operations,
Undo/Redo and save/reopen. A model-only check is insufficient: retained SVG nodes can still carry
an obsolete CSS preview transform even when saved ink vectors are correct.


## Spatial editing contract (16 October 2026)

`src/reflow/spatialLayout.ts` is the pure geometry owner for horizontal pressure, vertical rows,
condensing and rigid-selection constraints. The editor captures visible word/ink coordinates once,
previews absolute movement from that snapshot and commits final coordinates. Temporary handles do
not replay geometry, and per-spacer coordinate-basis dictionaries have been retired.

Horizontal movement uses spare room before pushing a neighbour. A contact inside a word snaps the
visible caret to its leading edge. That visible boundary divides the sides: subtraction moves the word on its left and
leaves words to its right fixed; addition targets the word on its right. Subtraction pushes earlier
words and wraps whole words onto earlier lines within the same paragraph. Reopening the current valid handle restores pushed/wrapped neighbours
from its baseline. A new edit invalidates old handle snapshots. Explicit paragraph/list boundaries
remain separate when overflow reaches them. Vertical subtraction closes blank rows and pushes occupied earlier rows upward, stopping at the page
top; actual tall-ink bounds constrain closure. Condense preserves explicit breaks, short rows and indentation.

Controls do not enter word pressure. Explicit semantic checkboxes follow their owner row. Unbound
checkboxes move with vertical rows; richer object attachments are deliberately not inferred. Shapes
and object-local ink remain independent. Taps, no-op, cancellation, Undo/Redo and save/reopen use the
same canonical positions. Detailed architecture and acceptance matrix:
[`NOTES-SPATIAL-LAYOUT.md`](../../../docs/architecture/NOTES-SPATIAL-LAYOUT.md).


## Saving when Notes backgrounds

Native idle-save notifications persist already delivered ink without a flush, input toggle or repaint.
Home completes the existing ordered native flush and checkpoint before scoped ink suspension.
A model-only thumbnail is then rendered from saved files (cover page if chosen, otherwise active
page) and atomically saved through the shell. This never captures, hides or refreshes the native
ink surface; the ruled editor’s older screenshot/toolbar-hiding fallbacks have been removed. Concurrent pause requests share the checkpoint, late previews cannot overwrite newer
owners/explicit close, and unchanged content does not rewrite its PNG. Save/preview failures are
reported on resume and can be retried. The page remains open for returning to Notes.
This is bounded lifecycle work, not an always-running service: Android force-stop/process death
before a checkpoint completes cannot be promised to finish its JavaScript work.

## Page attachments

Notes supplies one expanded-toolbar Attach action. It opens a small anchored menu for images,
audio, files, web links and arranging existing objects. Compact mode keeps six writing actions,
with Format with AI in Zoom's former slot; Zoom remains in expanded mode. The expanded rail uses
one column whenever its fixed controls fit, otherwise two columns, with no rail scrolling.

Select (the pointer beside Lasso) taps words or the topmost page object directly. Drag a selected
word to move it, or use image grips. Tapping Select again opens selection actions; drawing on blank
paper in this mode creates neither ink nor a lasso. Lasso retains group selection.

Attachments use the existing page-object geometry, history, movement and resize owners. Image
corner grips preserve the current aspect ratio, edge grips resize one axis, and the image centre
drags to move. Images and their page-local ink move together. Audio is a small
play/pause card with elapsed/total time; selecting an object exposes the existing manipulation
controls. Link cards open in the system browser; other file cards use Android's associated app.

The app copies user-picked files into the active data root's content-addressed `attachments/`
store; sidecars save only IDs and display metadata. Copies of pages and Undo retain those IDs.
Deleting a page object deliberately does not delete a shared resource needed by another page or
history. Include the attachments directory when moving/backing up the Notes data root. Images
are decoded with orientation support and optimized to at most 1600 pixels on the longest side;
other files are copied as-is, capped at 100 MiB. No broad new storage or microphone permission.

Images load once per workspace. Saved-page export and thumbnails await decoding and embed the
pixels, so image sharing does not depend on external URLs. Ordinary writing retains unchanged
image/widget DOM. Opening the picker checkpoints and uses the existing dialog handoff; late
results cannot insert into a closed/reopened/different page. No daemon lifecycle or waveform
policy changes. Native audio uses async preparation and audio focus, and releases on background
or close. Timer status is cached without DOM changes while the daemon owns writing; deliberate
play/pause state changes use the existing bounded control reconciliation. Pen activation shares
the checkbox single-owner contract, including temporary-dot cleanup and compatibility-click
suppression.
